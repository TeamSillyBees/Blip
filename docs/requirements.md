# Blip 首版需求

状态：2026-10-25 用户已整体确认并授权直接实现、验证与 commit。范围依据 2026-10-21 的两轮回答与整体确认整理。

2026-11-06 补充：用户要求支持通过 npm 安装，并使用成熟 CLI / 终端交互框架配置不同通知渠道。采用 npm 启动器加平台原生包分发，Go 端使用 Cobra 和 Charm Huh；提供新增、编辑、启停、删除和统一保存。此补充不引入服务端部署，公共 npm 发布单独执行。

## 已确认

- 本轮交付可运行首版、文档与必要测试，并在当前仓库提交 commit。
- 首版验收覆盖 Windows 上的 Codex CLI 与 Codex 桌面版；内部保留跨平台能力。
- 仅实现轮次完成、审批请求、用户输入请求三类提醒。
- 轮次完成指正常结束一轮回复；中断、取消和失败不发送完成提醒。
- 支持飞书、企业微信、Gotify、自定义 webhook；可同时配置多个目的地。
- 三类事件发送到所有启用的目的地，首版不引入分流规则。
- 2026-11-06 模板调整及补充：标题包含“完成／需要输入”、项目名和设备名，正文使用对话名及事件时间；时间按本机时区显示并标注偏移。需要输入时追加问题与 A、B、C、D 等选项。审批归为“需要输入”，附简短确认提示。默认模板不再显示会话 ID、轮次和回复摘要。
- 使用 Go 单文件命令行程序，提供本地配置与 Codex 接入的安装、卸载命令；保留已有配置，hook 信任由用户在 Codex 中完成。
- 输入提醒覆盖结构化提问工具，不识别普通正文中的问句。
- 审批提醒覆盖实际产生官方 PermissionRequest 回调的路径，明确记录版本和覆盖缺口，不承诺捕获所有实际等待场景。
- 完成提醒按会话与轮次正向核对正常结束记录，不将 Stop 或安静状态直接等同于完成。
- 飞书与企业微信采用群机器人 webhook；飞书支持可选签名密钥。参考 agent-notify 的分层设计，首版不引入其飞书企业应用私聊路线。
- 本地持久队列与后台发送进程负责去重、超时和有限重试；回调只负责快速入队，重启后继续未完成投递。
- 2026-11-06 后续调整：首次配置可编辑设备名称，默认当前计算机名，显示在通知标题中，同时保存在事件和结构化 webhook 中。URL 明文显示，Token 和签名密钥继续遮蔽，移除环境变量引用及冗余配置提示。
- 各目的地独立记录投递结果，失败目的地不阻止其他目的地。
- 自定义 webhook 使用固定 JSON 事件格式与 HTTP POST，支持静态请求头和 Bearer token，HTTP 2xx 视为成功；不实现请求体模板或脚本。
- 第一阶段不实现上述范围之外的产品需求。

## 验收约定

- Windows 上可构建并运行，提供配置示例、启动方式和接入说明。
- 三类规范事件能够通过本地测试服务投递到四类渠道；飞书和企业微信校验业务成功码。
- 重复事件、部分渠道失败、网络超时、进程重启均有针对性验证。
- 正常结束、结构化提问与审批回调使用脱敏事件样本验证；中断和子 agent 结束不产生根会话完成提醒。
- 安装与卸载保留非 Blip 配置，并验证包含空格和中文的路径。
- 不具备真实目标端凭据时，明确区分本地协议测试与实际渠道端到端验证；不把模拟测试声称为真实 Codex 全路径实测。

## 实施默认值

- 后台进程提供显式启动与停止方式；普通 `start` 不设置开机自启。按 2026-11-06 的后续要求增加 Windows 服务注册、自动启动及服务管理；仍不添加图形界面或云端服务。
- 完成事件读取本机 Codex 结构化会话记录，并持久保存读取位置；首次启动建立基线，不推送既有历史完成事件。
- 输入和审批使用官方 hook；不自动批准操作、不修改 Codex 的 hook 信任记录。
- 投递采用尽力去重的至少一次语义。接收端已经接收、但本地尚未记录成功时崩溃，重试仍可能产生重复提醒。
- 渠道凭据保留在本地配置，不写入事件、常规日志或版本库；按 2026-11-06 的后续要求移除配置中的环境变量引用支持。

## 已知能力边界

- 2026-10-21 的桌面版 26.1013.40934 / 内核 0.163.0-alpha.10.2 已实测异步提问工具 hook；该结论不代表所有版本和所有客户端路径。
- 同次测试的 request_permissions 未触发专用 PermissionRequest；其他审批路径与 CLI 仍需分开验证。
- PermissionRequest 表示审批申请被观察到，不能单凭该回调保证用户仍有未处理弹窗。
- 异步 PostToolUse 不表示用户已回答。首版按请求事件提醒，不维护“已回答”状态。
- Codex 会话记录格式不是稳定公开接口；升级后需要重新验证完成事件兼容性。失败结束缺少真实样本，不将其覆盖写成已实测。
