# 回调入本地持久队列，后台按目的地投递

通知渠道会超时或暂时不可用。Blip 的回调只持久保存规范事件，后台进程为各目的地分别保存投递状态、执行去重和有限重试，避免网络等待占住 Codex hook，也使重启后能够继续未完成的投递。

这增加了后台进程和本地状态管理成本；与同步发送相比，它保留了暂时断网时的通知。投递为尽力去重的至少一次语义，接收成功与本地成功记录之间崩溃仍可能造成重复；不承诺跨进程与外部渠道的严格恰好一次语义。

2026-11-06 补充：损坏记录隔离到独立目录并保留原始内容、诊断信息和事件标识，避免阻塞健康通知或在回放时丢失去重依据。隔离与收据更新、入队、清理共用短时文件锁；隔离前先保存事件标识，再移动原文件。所有目的地均结束的记录从最后一份终态收据起保留 7 天，待发或停用目的地的收据不因年龄过期。缺少失败时间的旧收据在迁移时重新获得完整保留期。
